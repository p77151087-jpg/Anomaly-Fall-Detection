# UR Fall 診斷

2026-09-18。候選形成前只讀 Train／Validation，沒有新增 Test 分數。[原始診斷](validation/course-ur-diagnosis.json)含47序列及 hash；本診斷分數來自既有混合模型 caucafall-yolo11-balanced-001。

## 已證實

Train 24/24 ADL 有有效特徵，共659窗口，每序列9–55個。Validation 23/23有合法事件分數，因此序列 unknown=0；但有效端點覆蓋只有64.32%（ADL59.06%、Fall72.77%）。「序列可判定」不等於整段影片每刻都有可靠骨架。

混合門檻0.360894在UR Validation得到TP7、TN7、FP1、FN8；Accuracy14/23=60.87%、F1=14/23=60.87%。正常序列分數0.0633–0.4315，跌倒0.0373–1.0009，分布重疊。

誤報為adl-20。漏報為fall-19、18、13、29、09、07、25、30；這八支仍有合法分數，直接判定原因是最大合法事件分數未超門檻，不能把它們都歸因於「完全看不到人」。例如fall-19只有5個有效特徵，但fall-09有25個，單看窗口數無法解釋所有漏報。

若僅用同一混合AE重做UR Validation診斷性門檻搜尋：F1目標會選到23支全部陽性（TP15、FP8、F1約78.95%）；balanced accuracy目標選到TP8、TN7、FP1、FN7。這說明有限、不平衡的Validation可使F1單一目標偏向多報警；這些數字沒有改寫舊run門檻，也不是新的正式模型成績。

快取記錄含track_gap/no_person等失效原因。quality_counts計算的是「端點×track」記錄，可能同時出現有效與失效track，不能直接當影格缺失百分比。正式coverage使用去重後的scheduled endpoint分母。30幀窗口有缺漏會失效；即使已有1–2個有效窗，也可能尚不足連續三窗事件。

## 尚未證實的因果假設

- 混合資料的尺度／動作分布差異可能使UR重建誤差不容易分離；用UR-only候選檢驗，不能先認定這是主因。
- 每序列窗口數不同可能讓長ADL主導AE；比較均衡取樣。
- latent16可能限制AE對異常的重建能力；比較固定容量候選。
- 遮擋、側躺、姿態域差异與追蹤中斷可能讓起跌窗口不可用；需逐窗和影片對照，現有序列標籤不足以證明精確因果或量測延遲。

沒有證據支持單純增加epoch即可可靠改善。這次只實施協定列出的三個AE候選；不在看到Test後放寬骨架品質、窗口或事件要求。
